# Wind 增量更新与历史修订

本地 `wind_daily tick` 默认走增量采集，不再每天完整下载全市场 300 日 OHLCV。无需恢复任何 GitHub 触发器；Trading Desk、登录就绪确认和跨机器独占规则见 [本地调度](WIND_LOCAL_DAILY.md)。

## 正常每日与漏日

读取当前 `latest.wind_vintage` 对应的已发布 Wind 版本，核对单位 profile、最新产物 SHA、逐日行情/状态 SHA。只使用这一个供应商版本，不混入 iFinD、AKShare 或任意私有缓存当作基线。损坏或不存在的行情分区当作缺口，不继续使用其中的数据。

Wind 重新给出已完成交易日、当前股票池、上市日和股本。目标窗口取最近 **300 个真实交易日**：

- 正常更新：复用 299 日，下载新增交易日的原始全字段行情和原生复权 OHLC。
- 开机漏日：按每只股票实际缺口分组，只合并相邻的缺失交易日；不会为了补两个不相邻日期，把中间已有日期也重取。
- 新股/新增代码：从上市日与窗口起点的较晚者开始建立基线，不查询上市前历史、不造线。
- 空白行情保持未观察，不前填、不把缺失推断成停牌。供应商后来补上旧缺口，下次更新可以补入。
- 已发布窗口完整且没有新交易日时，定时 tick 直接跳过，不再次连接 SDK。

完全空的数据目录首次仍需下载 300 日。已有其他供应商或 profile 改变时拒绝静默拼接；应先重新做本机 canary，再显式执行 `wind_collect collect` 建立经过审核的完整 Wind 基线。仅调整限流参数也会改变当前 profile 哈希，需保持与基线一致或安排显式重建。

## 复权与修订检查仍需要少量历史请求

不能只追加一根线就假定历史永不变化。每次真正增量更新执行：

1. **所有股票、整个窗口：** 用两个单字段矩阵查询原始收盘价和原生复权收盘价，核对已有日期的价格、观察键集合和已验证因子。这不是重取整套 300 日 OHLCV；空值、轴错位和无穷值均校验。历史收盘价或复权基准变化时，只对受影响股票重取窗口内原始全字段与原生复权 OHLC，并重新检查同一日整组 OHLC 的乘法映射，绝不靠一个新因子直接缩放旧历史。
2. **轮换完整核查：** 股票按代码 SHA256 分成 20 组，每次成功发布核查一组（约 5% 股票）的整窗原始字段和原生复权 OHLC，覆盖成交量、额、开高低、换手、前收等只查收盘无法发现的修订。检查点保存核查证据，发布成功才推进组号；失败重试不会错误地前进。
3. **新日期/旧缺口：** 每次新增的原始与复权 OHLC 都实际成对取回并校验；未变化的旧日期复用已验证 OHLC/因子，并通过本次整窗收盘探针确认没有换基。

因此，收盘/复权修订在下次真正更新时核对；非收盘字段的深度修订，最迟在一轮 **20 次成功更新**中的对应核查组发现，而非保证自然日内或当天全部发现。期间仍保留先前已验证观察。若供应商宣布大范围修订或要求立即复核，可安排独占窗口执行显式全量核查：

```bash
.venv/bin/python -m china_stock_engine.wind_collect incremental \
  --end YYYY-MM-DD --profile .private-stock-data/wind/profile.json \
  --data-dir data --exclusive-window --audit-all
```

`--audit-all` 会对全部股票请求整窗全字段，是人工修订核查的例外，不是日常默认。候选仍需 `wind_publish` 校验后才能提升；该命令不自动发布、不 Git 推送。供应商在探针与配对下载之间再次修改价格，导致同批数据不一致时，整次候选失败，稍后重试，旧 latest 保留。

## 知识时间、断点与发布

复用的是先前验证过的数据，不能把今天发现的修订倒填为过去已经知道。新候选保留来源 vintage 与核查策略；新窗口的因子重新形成完整、同一验证时间的 300 日批次，`known_at` 为本次实际验证时间。旧供应商事实与 Wind 迁移基线不改写。滚动每日版本留存规则不变，历史逐日复现应固定相应 Git commit。

检查点的复用键包含 profile、起止日期、来源 vintage、核查组和核查模式。每只股票保存原始行情、因子 SHA 及核查元数据；中断后复用已完成股票的结果，未完成批次重试。另一个发布者推进了来源版本时，旧来源的候选被拒绝，须对当前版本重建，不能覆盖新修订。

最终候选在本地拼成完整 300 日工作集，重新运行筛选、质量与 SHA 校验。只有成功后才切换生产并轮换旧每日版本；采集或发布失败不影响当前 latest。已有 900 MB 容量门和原历史保护继续生效。

## 状态与 Windows 验收

`wind_candidate.json.incremental`、归档 `candidate_receipt.json`、生产 `wind_publication_status.json.incremental` 以及本地调度结果包含：

- `source_vintage`、`audit_bucket/next_audit_bucket`：来源和核查进度；
- `reused_rows`、`gap_rows_downloaded`：当前计划复用和补齐的行数，包含已完成检查点的结果；
- `raw_rows_downloaded_this_attempt`：本次进程实际下载的完整原始行情行数，包含核查/修订重取，不包含两个单字段探针；
- `repairs`：新股/缺失基线、复权变化、历史收盘或完整字段修订的股票及原因；
- `checkpoint_reused_codes`：本次直接恢复检查点的股票数。

Windows 先按原说明完成官方 SDK 与单位 canary，再在独占窗口做增量小样本：

```powershell
.\.venv\Scripts\python.exe -m china_stock_engine.wind_collect incremental `
  --end YYYY-MM-DD --data-dir data --batch-size 3 `
  --codes 600000.SH,000001.SZ,920001.BJ `
  --profile .private-stock-data/wind/profile.json --exclusive-window
```

选当前已发布或最新已收盘交易日。`--codes` 始终是不能发布的样本；同日样本只验证历史复用/探针，新增日期下载还需下一交易日或隔离测试数据验收。检查原始/复权轴、空白、核查记录和实际单位，再使用日常 `wind_daily tick`。不要把 Mac 原生矩阵记录、离线模拟或同日零缺口验收写成 Windows 次日增量已跑通。

本轮离线测试覆盖 300 日拼接、新增/离散缺口、损坏分区、新股、复权换基、历史收盘/成交量修订、原生复权 OHLC 不兼容、供应商批内变化、断点恢复、旧基线候选拒绝及失败不移动生产。新的实机全市场增量耗时和 Windows 原生验收尚无记录，不承诺固定几分钟。
